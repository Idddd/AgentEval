# V2 新建流程：真实集成与 Mock 的差异

核对日期：2026-10-23。以当前 `live-form.tsx`、`live.tsx`、`nmgr-api.ts`、`nmgr.ts`、`nmgr-draft-sync.ts` 与 Mock `app.tsx` 为准。

## 本次已简化

Guardrail 和 Profile 新建时均自动生成 `gr-UUID` / `pf-UUID`，不显示 ID 输入框。名称不参与 ID 生成；同名的新表单得到不同编号。一次表单中的保存失败、重新填写和重试沿用同一个编号。编辑与创建新版本保留原编号，详情仍可查看。

自动生成在表单首次打开时完成，不改已有后端命令协议。后端继续校验格式和唯一性。浏览器整页刷新会丢失尚未保存的表单；本次没有增加草稿跨刷新恢复能力。

## 仍有 8 类集成差异

这些是差异类别，不是要求用户额外执行 8 个步骤。其中前 4 类影响进入/填写表单，第 5–7 类涉及保存、引用校验和异常恢复，第 8 类发生在后续上线阶段。

| # | 项目 | Mock | 真实版 | 原因与建议 |
|---|---|---|---|---|
| 1 | 登录与角色 | 浏览器演示角色可切换 | NeMo 账号密码只在后台配置，后端维护会话。本地测试直接进入，固定身份由后台配置；前端没有凭据输入或角色切换 | 保留服务端角色权限；本地模式仅供 loopback 测试，内网多用户需独立身份接入 |
| 2 | Control Unit | Guardrail 新建可在演示部门中选择 | 从账号映射取得，只读 | 避免跨部门创建；应由管理员维护归属 |
| 3 | Sign-Off Approver | 可选择示例审批人姓名 | 不显示姓名选择；由同部门独立审批角色处理，不能自批 | 当前没有指定个人审批人的端到端实现；需要个人路由时应另做账号目录和审批指派 |
| 4 | Source | 新建表单没有同样的服务来源选择 | User 表单不显示 Source；Tech 保存 Guardrail 实现时选择 NeMo / 已配置的 F5，之后固定。Profile 根据同源已发布 Guardrail 自动推导 | 技术来源由 Tech 决定，后台拒绝 User 提交 provider；已有记录保留原绑定 |
| 5 | 保存与同步 | 写浏览器演示状态 | PostgreSQL/MariaDB 保存业务记录；新 Guardrail 等待 Tech 选择来源，NeMo 实现保存时才创建 Policy 草稿，Profile 对应 NeMo Guardrail 草稿，并回读核对。F5 在初次保存时只建 Marketplace 记录，Scanner/Project 在后续评测/发布阶段创建 | User 保存只提交需求；Tech 选 NeMo 后保存实现触发同步，F5 仍在评测时创建 Scanner；发布另行执行 |
| 6 | Profile 引用范围 | 至少一个已部署 Guardrail | 同部门、同来源、已发布 Guardrail；还需有效的后端发布版本、规则和执行方向，F5 还校验实例一致。NeMo 在保存草稿时检查这些发布证据；F5 初次保存只做本地引用校验，完整证据校验在提交审批等后续阶段执行 | “至少一个已部署”的要求两版已有；新增的是来源隔离及后端发布证据，不能混合 NeMo/F5 组成一个 Profile |
| 7 | 同步失败及冲突处理 | 本地状态即时保存 | 检查工作区版本；后端结果不确定时需核对，不能重复盲建。部分失败可修正后重试；NeMo Profile 创建结果丢失时可能需要原始远端资源 ID | 只在异常恢复时出现；应继续由系统尽量自动处理，而不是放进普通新建表单 |
| 8 | 保存到生效的后续阶段 | 本地模拟状态，Profile 审批即可模拟激活 | Guardrail 要有真实实现/评测证据再审批发布；Profile 审批后仍需 Tech 执行真实编译、冻结版本测试和发布；应用流量接入另行配置 | 这是后续上线流程，不是新增表单字段；不可用 Mock 成功状态替代后端结果 |

## 另有 3 类 UI 差距，不能归因于接口必需

| # | 差距 | 当前影响 | 建议 |
|---|---|---|---|
| 1 | Profile 的 BU/SU、Agent Type、Data Type | Mock 可填；真实表单未开放，新建暂存空值 | 属于业务元数据，明确用途后可补齐，不必要求 NeMo 原生支持才能存于 Marketplace |
| 2 | Profile 的 Alert Threshold / Metric / Window | Mock 可设置；真实版未开放，监控数据/告警尚未接通 | 先完成指标与告警接入，再开放可生效设置，避免只展示无实际效果的选项 |
| 3 | Mandatory Guardrail 自动选择 | Mock 按位置自动勾选并锁定必选项；真实版目前只显示标记，漏选由后端拒绝 | 应按已发布版本和位置自动勾选；这是可以改善的填写体验，不是集成要求用户多操作 |

本次仅实施 ID 自动化，其余差异为代码核对清单，没有顺带改变权限、同步、审批、监控或发布行为。
